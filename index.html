Features

Hardening that actually understands your code

Lurith parses your source with tree-sitter before and after transforming it — no blind string swaps, no broken output.

Scope-aware renaming

Locals, parameters, loop variables, upvalues and local functions get new names — while globals, properties and Luau types stay untouched.

Virtualized strings

Literals become randomized string.char(...) fragments with shuffled pools — and integer constants get masked at stronger levels.

Polymorphic VM families

Pick classic, balanced, packed or staged interpreter structures — or let auto randomize.

Integrity verification

Every code word and constant is verified on every call in integrity-enabled levels, so tampering with the generated build is caught per call.

Luau-safe transforms

Backtick interpolation, --!strict directives and Luau type syntax are preserved so output still runs in normal Roblox environments.

Never executes your code

Uploaded source is analyzed, never run. No loadstring, no hidden execution — your script is just transformed and returned.

Getting started

Lurith is a Discord bot locked to one server. Join that server, then obfuscate scripts straight from chat.

Protection levels

Levels trade runtime speed for obfuscation strength. The table above summarizes each; here is the detail:

  • low — validates syntax, keeps formatting and comments, protects long strings.
  • normal — adds local renaming, minification, light integer masking and one-time integrity with per-call code/constant checks.
  • medium — enables the polymorphic VM with safe auto-selection and cached integrity.
  • high — broader auto-VM, native opaque predicates and bounded state wrappers.
  • very-high — maximum VM variation, broadest selection, per-call integrity. Slowest, heaviest. Booster-only.
  • maximum — densest VM/native-flow variation, broadest auto-VM, always-on integrity. Booster-only.
💡
Tip: start with normal or high. very-high and maximum are booster perks — boost the server to unlock them.

VM families

Use .vmcfg to choose which interpreter structure the generated VM uses:

  • classic — linear dispatcher, table code, rolling checksum formula.
  • balanced — binary dispatcher with a Fletcher formula (requires normal+).
  • packed — bucket dispatcher with lazy varint-decoded bytecode (requires high+).
  • staged — two-state fetch/execute with grouped ALU (requires high+).
  • auto — the config-selected randomized profile.

Source directives

Control how Lurith treats specific functions with comment directives placed directly above them.

LUA
--@lurith-vm
local function calculateScore(base: number, multiplier: number): number
    local score = 17
    for index = 1, multiplier do
        score += base
    end
    if score > 100 then
        score = 100
    end
    return score
end

--@lurith-no-vm      -- keep this function native (never virtualize)
--@lurith-hot        -- for known per-frame / high-frequency functions
  • --@lurith-vm — force VM compilation; you get a clear error if the function is unsupported.
  • --@lurith-no-vm — prevent automatic selection.
  • --@lurith-hot — mark functions that should stay native for performance.
  • --@lurith-vm <level> — build one function's VM at a specific level, e.g. --@lurith-vm maximum.
  • --@lurith-minify / --@lurith-no-minify / --@lurith-strip-comments / --@lurith-keep-comments — per-script minification and comment controls.

Watermark & output

Every generated build starts with a stable watermark:

LUA
-- [obfuscated by Lurith v5.0.0 | https://discord.gg/XSYDVYbqNz ]

A shebang or Luau mode directive such as --!strict is kept above the watermark. Re-obfuscating a file replaces the old watermark instead of stacking duplicates. Artifacts are returned as *.lurith.txt, and successful replies include a SHA-256 fingerprint of the output.

Limitations

Lurith is not a whole-program commercial VM, and it doesn't claim to be undeobfuscatable — no obfuscator is. It performs parser-backed scope transforms and compiles supported functions into a shared polymorphic VM.

⚠️
Complex closure capture, unrestricted multi-return propagation, coroutine yielding and mixed indexed assignments are kept native on purpose — Lurith prefers correct output over aggressive but broken transforms.
